# 任务模块开发约束与基础契约

本文件适用于 `tasks/`，同时遵循 [Android 模块约束](../../../../../../../../AGENTS.md)。需求以 [spec.md](../../../../../../../../../spec.md) 为准。

本目录覆盖 R04–R06、R14、R16–R19、R31、R33–R34。请求契约已接入同一应用状态数据库的持久队列、提交／观察、单任务协调器与阶段控制／恢复。已注册本地候选只读快照和个人 OneDrive 浏览／快照处理器；前台显式调用 `TaskCoordinator.drain()` 驱动已注册处理器，后台与任务页在步骤 09 接入。协议 fixture 与真实 SQLite 证据见 [第二阶段记录](../../../../../../../../verification/phase-2.md)。

## 提交对象与去重

[TaskRequests.kt](api/TaskRequests.kt) 提供元数据同步、单格式复制／下载、单封面加载及已读写回请求。格式资源使用完整书籍身份、格式与后端定位，可附带源版本比较前提；已读请求保存同书库的非空书籍集合、动态栏目和明确 Boolean。`FrozenSet` 在构造时复制并去重，内容不随调用方修改，集合顺序不影响等价性；批量下载和封面在第二阶段按这些单资源请求拆分，不能重新查询并扩大提交集合。

`RequestKey` 包含完整请求及必要依赖，包含栏目、目标值、定位、版本比较前提与快照新鲜度，不包含触发来源。只可复用等价的未完成请求；用户主动请求等价自动任务时，持久队列负责复用并提升，而非重复传输。`SnapshotFreshness.AfterWrite` 绑定具体写回任务，要求其 `SOURCE_COMMIT_CONFIRMED` 依赖，不能复用写前的普通同步或另一写回的刷新。

相关写回顺序与请求等价性分别表达：`relatedWriteKeys()` 返回书籍完整身份与栏目键，目标值不参与该键；集合有交集的写回必须由提交事务建立顺序约束。`SUCCESS` 等待依赖完整成功；`SAFE_TERMINAL` 等待依赖的整个流程到达已记录的安全终点，可用于允许前一个已明确失败／放弃的意图之后执行新意图。提交不明、已提交但仍需刷新／恢复的任务，即便显示失败或取消，也不能仅因 `Finished` 就被判为安全终点。`SOURCE_COMMIT_CONFIRMED` 仅供写后刷新，在写入确认后满足，不要求整个写回已完成，避免刷新与写回完成互相等待。提交事务校验依赖所属书库、类型及完整相关写回顺序；新节点只指向已有节点，且不提供依赖修改接口，因此不能建立自依赖或循环。

## 优先级与调度边界

[TaskContracts.kt](api/TaskContracts.kt) 保存不透明 task ID、书库身份、原始来源、当前优先级、同级排队序号、依赖、阶段、静态进度、结果、提交证据与阶段控制能力。书库身份沿用每个有效书库代次独立的 `LibraryId`，不按源数字 ID 匹配任务。enum 具有显式持久化字符串 code，不能保存 ordinal；封闭类型的序列化使用 [TaskCodec](persistence/TaskCodec.kt) 的版本与显式标签；schema v2 通过非破坏迁移加入任务和依赖表。

用户下载、为打开而下载、手动同步、已读／未读写回为高优先级；可见封面、启动同步、已下载格式更新为低优先级。必要前置请求及后续阶段沿用父请求来源和优先级，不按操作类型自行降级。自动任务提升保留原始来源，并保存此次用户来源和新分配的高优先级序号；必要前置任务也必须提升。序号由持久队列事务分配，不能由时钟或 WorkManager 的启动顺序代替。

`compareSchedulingPositions` 只比较优先级和同级序号，不是调度器。调度先筛选当前激活书库、网络／授权条件、依赖满足且未暂停的任务，等待项不阻塞无关可执行任务；同一时间只执行一个任务，不自动抢占，在单书／单格式／单封面子任务之间重新选择。相关写回顺序及源提交安全边界优先于一般排序；写入确认到写后刷新之间保留执行权，不插入无关任务。

## 写回证据与重试

写回依次表达取最新源快照、准备、提交、重新获取、导入和必要恢复检查。`TaskRecord.commit` 持久保留源提交证据，进程在刷新阶段中断也不能丢失写入事实；该证据不成为页面已读覆盖。

- `NotCommitted`：失败记录标明失败阶段，可按安全检查重试；不得以旧暂存数据库绕过重新校验。
- `Confirmed`：写入已完成；刷新失败仅从 `WRITE_REFETCH` 重试，页面继续使用旧导入值。只有重新导入成功才报告整个写回 `Completed`。
- `Unknown(recoveryRecordId)`：结果不明，保留恢复资料并从 `RECOVERY_CHECK` 处理；先核对最新源状态，不能直接再次提交，也不能静默放行后续相关写入。

`CompletedWithBookFailures` 在有效目标已写入并重新导入后保留逐书失效原因；整体失败可通过带书籍身份的错误定位失效对象。不能把部分条目无效伪装为全部成功。失败使用结构化存储原因、栏目失效或书籍身份变化，不保存异常全文、令牌或 URL。取消结果仍保存提交证据，不撤销已提交的源修改；源提交阶段不能直接暂停／取消，执行器在可记录的安全边界处理控制请求。其他阶段的暂停、取消、继续和重试能力由实际处理器提供，接口不保证任意阶段均支持控制。未知进度总量用文字呈现，状态事件与有效缓存发布事件分别表达。

## 启动与实现状态

`StartupSyncSetting` 默认关闭，仅定义设置值。后续开启时，每个进程首次由用户打开主界面且已有配置才提交一次低优先级同步；后台恢复启动、返回阅读器和 Activity 重建不触发新同步。本阶段没有启动钩子、周期请求或假成功事件。`DurableTaskQueue` 实现提交与观察，`SubmissionResult` 区分新建、复用、提升与拒绝。未注册处理器的功能不能通过协调器提交，当前应用容器注册本地及 OneDrive 候选处理器；不创建假源访问或假完成入口。

AC05 的持久调度、并发唤醒、控制、有限重试／退避及阶段恢复以注入处理器验证；后台、通知、重启和真实源访问仍待后续阶段，不能用协议测试关闭这些验收。

## 源访问边界

生产任务处理器通过存储后端访问源，不将源客户端或任意路径暴露给提交方。错误、事件和日志不得携带凭据或原始响应。

## 执行与恢复协议

- [DurableTaskQueue](persistence/DurableTaskQueue.kt) 的事务分配序号并保存请求、来源、提升、依赖、阶段、结果、重试期限及私有暂存代次／源版本。所有协调器必须使用应用容器共享的同一个 repository 与执行锁；不能在 Activity 或 worker 中另建执行器状态。条件函数只读取已知状态，不在选择事务中隐式访问源。
- [TaskCoordinator](persistence/TaskCoordinator.kt) 连续执行一个资源的阶段；完成、等待、失败或用户安全暂停后才重新选择资源。处理器须在支持控制的阶段循环中调用 `checkControl()`，收到控制异常后关闭句柄并停止工作；不能忽略控制后继续发布。阶段控制由实际处理器提供，不承诺任意阶段可中断。
- 进入源提交前持久保存 Unknown 证据；处理器确定提交结果后立即调用 `recordCommit()`，确认写入不得退回未写入。安全失败的未提交写回仅在后来相关意图尚未开始时可重试；后来意图开始后旧任务失去重试能力，新的用户意图须重新入队，不能重放旧目标颠倒顺序。已确认写回从 WRITE_REFETCH 恢复，不重放提交；未知提交只能先到 RECOVERY_CHECK。已确认但未刷新、暂停或失败的流程保持当前书库的执行屏障，不能仅因 Finished 放行相关写回；切换书库停放旧库任务，不能阻塞新库的独立工作。
- 恢复、继续及重试都先调用处理器 `recover()` 重新核验源版本与暂存。队列不会仅凭 Running 或曾存在暂存判成功。瞬时网络错误最多自动重试三次，指数退避与服务端等待取较长者；离线等待和永久错误分别处理，下一次唤醒不忙循环。
- `CandidateConfiguration` 只承接内部注册的配置源访问，使用当前选择代号、后端和不含凭据的授权会话 ID，首次发现可由 `beginCandidate()` 保存尚无稳定位置的会话，并用 `resolveCandidate()` 原子补上稳定目录，不分配 LibraryId，不能带书籍或写回依赖。条件提供方须核对授权会话；新账号会话或重选使旧代号不能再被选中，取消候选任务在控制事务中撤销旧代号，执行中的旧候选结束不能发出成功缓存事件。真正验证后的发布仍须调用状态库的代号校验事务，禁止先检查再无条件写入当前配置。
- 状态事件在数据库提交后发出；观察者重新读取持久状态。`cachePublished` 只能在实际完整缓存发布之后使用；阶段完成、临时文件生成或源写入确认都不等于缓存发布。生产处理器须遵守后续传输／导入的原子发布契约。

## 本地快照候选任务

[LocalSnapshotTaskHandler](local/LocalSnapshotTaskHandler.kt) 仅支持本地 `local_snapshot` 候选请求，使用现有选择代号；本地持久授权没有 OAuth 会话时以该代号作为不含凭据的授权上下文标识，不调用目录发现来清空已有稳定位置。恢复重新获取源并检查版本、日志与私有 SQLite 完整性。复制块边界及私有发布前检查控制和选择代号；暂停／取消清理本次暂存，重选结果不显示到新配置。成功须经统一元数据导入器完整验证并在状态库事务中发布身份／代次，之后才发 `CacheChanged`；快照按任务与不可变尝试代次隔离。取消会撤销选择代号，再次验证必须取得新的当前代号。

[LocalSnapshotViewModel](../ui/LocalSnapshotViewModel.kt) 恢复只读取本地配置和持久队列，显式加载／继续／重试才唤醒共享协调器。当前没有后台唤醒或自动启动源访问。

## OneDrive 候选任务

[OneDriveCandidateTaskHandler](onedrive/OneDriveCandidateTaskHandler.kt) 将本人 drive 发现、完整目录加载及快照获取放入同一持久执行锁。候选请求保存目录 item ID，不保存 nextLink；旧请求页码仅为持久格式兼容保留，执行／恢复均从第一页重新取完服务器分页。每个服务器页边界检查任务控制，完整结果按 task ID 原子保存；仅在当前选择代号与授权会话仍匹配且任务成功时可读，缺少完整标志的旧分页结果不可用于本地翻页。目录结果不能绑定书库身份；选择根通过状态库比较代号的事务换代。快照前再次核对账号／drive，日志与版本冲突拒绝，快照完整导入成功后发 CacheChanged；失败保留旧有效导入。

[OneDriveCandidateService](onedrive/OneDriveCandidateService.kt) 只负责显式提交、根选择和私有恢复查询；恢复不联网。重新登录产生新的授权会话，旧任务不得复用令牌访问新账号。UI“浏览／切换到 OneDrive”显式切换当前后端，进入目录显式提交完整加载任务，本地分页只切换已加载列表，不访问 Graph、不提交任务；这些操作不激活书库；只有点击选择当前目录才保存稳定根位置。页面导航取消不选择新目录。已选位置在重新登录后显式验证时重新建立会话候选，并由后端核对实际账号。源快照交给统一元数据导入器；没有上传、源删除或书籍副本发布。

## 完整元数据导入

两后端候选同步均调用 `MetadataRepository`，只有结构解析、完整索引与快照原子发布成功才完成并发出缓存事件；目录浏览不会发出缓存事件。发布事务同时记录任务完成，完成后不再接受暂停／取消；事务复核选择代号与任务暂停／取消标记，过期结果不能激活新配置。恢复重新取得源快照及完整导入，不凭旧阶段或暂存文件宣称成功。当前候选同步的源访问与导入在同一可恢复执行阶段完成，支持块边界控制；完整后台阶段进度留步骤 09。
