# 任务模块开发约束与基础契约

本文件适用于 `tasks/`，同时遵循 [Android 模块约束](../../../../../../../../AGENTS.md)。需求以 [spec.md](../../../../../../../../../spec.md) 为准。

本目录覆盖 R04–R06、R14、R16–R19、R31、R33–R34 的任务基础类型。当前只有请求、调度信息、状态及提交／观察接口，没有持久队列、执行器、后台任务或 UI 接入。实际验证见 [第一阶段记录](../../../../../../../../verification/phase-1.md)。

## 提交对象与去重

[TaskRequests.kt](api/TaskRequests.kt) 提供元数据同步、单格式复制／下载、单封面加载及已读写回请求。格式资源使用完整书籍身份、格式与后端定位，可附带源版本比较前提；已读请求保存同书库的非空书籍集合、动态栏目和明确 Boolean。`FrozenSet` 在构造时复制并去重，内容不随调用方修改，集合顺序不影响等价性；批量下载和封面在第二阶段按这些单资源请求拆分，不能重新查询并扩大提交集合。

`RequestKey` 包含完整请求及必要依赖，包含栏目、目标值、定位、版本比较前提与快照新鲜度，不包含触发来源。只可复用等价的未完成请求；用户主动请求等价自动任务时，持久队列负责复用并提升，而非重复传输。`SnapshotFreshness.AfterWrite` 绑定具体写回任务，要求其 `SOURCE_COMMIT_CONFIRMED` 依赖，不能复用写前的普通同步或另一写回的刷新。

相关写回顺序与请求等价性分别表达：`relatedWriteKeys()` 返回书籍完整身份与栏目键，目标值不参与该键；集合有交集的写回必须由提交事务建立顺序约束。`SUCCESS` 等待依赖完整成功；`SAFE_TERMINAL` 等待依赖的整个流程到达已记录的安全终点，可用于允许前一个已明确失败／放弃的意图之后执行新意图。提交不明、已提交但仍需刷新／恢复的任务，即便显示失败或取消，也不能仅因 `Finished` 就被判为安全终点。`SOURCE_COMMIT_CONFIRMED` 仅供写后刷新，在写入确认后满足，不要求整个写回已完成，避免刷新与写回完成互相等待。后续提交事务须校验依赖所属书库、类型、循环及完整相关写回顺序。

## 优先级与调度边界

[TaskContracts.kt](api/TaskContracts.kt) 保存不透明 task ID、书库身份、原始来源、当前优先级、同级排队序号、依赖、阶段、静态进度、结果、提交证据与阶段控制能力。书库身份沿用每个有效书库代次独立的 `LibraryId`，不按源数字 ID 匹配任务。enum 具有显式持久化字符串 code，不能保存 ordinal；封闭类型的序列化标签和 SQLite schema 在第二阶段定义。

用户下载、为打开而下载、手动同步、已读／未读写回为高优先级；可见封面、启动同步、已下载格式更新为低优先级。必要前置请求及后续阶段沿用父请求来源和优先级，不按操作类型自行降级。自动任务提升保留原始来源，并保存此次用户来源和新分配的高优先级序号；必要前置任务也必须提升。序号由持久队列事务分配，不能由时钟或 WorkManager 的启动顺序代替。

`compareSchedulingPositions` 只比较优先级和同级序号，不是调度器。后续调度先筛选当前激活书库、网络／授权条件、依赖满足且未暂停的任务，等待项不阻塞无关可执行任务；同一时间只执行一个任务，不自动抢占，在单书／单格式／单封面子任务之间重新选择。相关写回顺序及源提交安全边界优先于一般排序；写入确认到写后刷新之间保留执行权，不插入无关任务。

## 写回证据与重试

写回依次表达取最新源快照、准备、提交、重新获取、导入和必要恢复检查。`TaskRecord.commit` 持久保留源提交证据，进程在刷新阶段中断也不能丢失写入事实；该证据不成为页面已读覆盖。

- `NotCommitted`：失败记录标明失败阶段，可按安全检查重试；不得以旧暂存数据库绕过重新校验。
- `Confirmed`：写入已完成；刷新失败仅从 `WRITE_REFETCH` 重试，页面继续使用旧导入值。只有重新导入成功才报告整个写回 `Completed`。
- `Unknown(recoveryRecordId)`：结果不明，保留恢复资料并从 `RECOVERY_CHECK` 处理；先核对最新源状态，不能直接再次提交，也不能静默放行后续相关写入。

`CompletedWithBookFailures` 在有效目标已写入并重新导入后保留逐书失效原因；整体失败可通过带书籍身份的错误定位失效对象。不能把部分条目无效伪装为全部成功。失败使用结构化存储原因、栏目失效或书籍身份变化，不保存异常全文、令牌或 URL。取消结果仍保存提交证据，不撤销已提交的源修改；源提交阶段不能直接暂停／取消，实际执行器应在可记录的安全边界处理控制请求。其他阶段的暂停、取消、继续和重试能力由实际处理器提供，接口不保证任意阶段均支持控制。未知进度总量用文字呈现，状态事件与有效缓存发布事件分别表达。

## 启动与实现状态

`StartupSyncSetting` 默认关闭，仅定义设置值。后续开启时，每个进程首次由用户打开主界面且已有配置才提交一次低优先级同步；后台恢复启动、返回阅读器和 Activity 重建不触发新同步。本阶段没有启动钩子、周期请求或假成功事件。`TaskQueue` 仅声明提交与观察，`SubmissionResult` 区分新建、复用、提升与拒绝。

AC05 的真实调度、持久化、重启恢复、控制、有限重试／退避、通知和真机验收均留待后续阶段。

## 源访问边界

生产任务处理器通过存储后端访问源，不将源客户端或任意路径暴露给提交方。错误、事件和日志不得携带凭据或原始响应。
